Every rule here was measured on this project. The defaults are not the fast path.

## Getting the file

Payload media goes through **`mediaFrom(value, preferredSize, fallbackAlt)`** from `src/lib/media.ts`,
never `media.url` directly. It picks a generated size, falls back through smaller ones, and strips the
dashboard origin (`serverURL` points at the dashboard host; `next/image` rejects it as an
unconfigured remote host, and visitors have no business reaching it).

Sizes: `thumbnail` · `card` · `cardWide` (16:9 crop) · `content` · `hero`.
**`cardWide` is deliberately outside the fallback chain**: ask for it by name, so a cropped tile can
never substitute for an in-article or hero image.

Static marketing pages have no CMS behind them. They read `src/lib/static-blur.ts`, generated by
`scripts/generate-blur-placeholders.mjs`. **Server Components only**: a client component takes the
string as a prop, see `FullBleedVideo`.

## Rendering it

- **Always give `sizes`.** Without it `next/image` assumes `100vw` and ships a desktop-width file to a
  phone. Match the real layout, for example
  `sizes="(min-width: 1440px) 480px, (min-width: 1024px) 33vw, (min-width: 640px) 50vw, 100vw"`.
- **`priority` on the LCP image only**, typically one hero per page. On everything else it competes
  with what the visitor is actually looking at.
- **Everything below the fold stays lazy.** That is the default; do not switch it off.
- **`placeholder="blur"` costs real bytes.** A `blurDataURL` is a few hundred characters of base64,
  close to incompressible, on the critical path. Worth it above the fold, expensive in a long list:
  see how the blog prunes them (`blog-content` skill).
- Photos go through `next/image`. **Video does not**: Next has no video pipeline, so it is served as a
  plain optimised static file from `public/videos/`, produced by `scripts/optimize-hero-video.mjs`
  (VP9 and h264 at 720 and 1280, no audio, plus a poster). One hero went 8388 KB to 734 KB on a phone.

## Uploads

`src/collections/Media.ts` downscales to a **1920px** long edge by default (`maxDimension`, editable
per upload) and converts to WebP, generating four sizes. Extra formats (AVIF, JPEG, PNG, WebM, MP4)
come from the sharp and fluent-ffmpeg already installed: **do not add a conversion library**.

ALT text and slug are derived from the filename by `MediaAutofill`; an editor reviews them. Video
encoding is CPU-heavy, so expect a wait.

## Verifying

- **Counting blurred images on a live page returns zero.** `next/image` drops the placeholder once the
  real file decodes. Grep the served HTML for `data:image/webp;base64,` instead.
- Measure transfer at a narrow viewport and a wide one, not just one.
- `images.localPatterns` in `next.config.ts` must keep listing `/images/**` next to Payload's path:
  setting that key at all turns `next/image` into an allowlist.
