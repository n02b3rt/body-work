## 2026-07-29: components split in two — an element library, and saved compositions

- **Done:** the "components" idea was doing two jobs badly, so it is now two things. **The element library** (`src/fields/elements/`) is 16 parameterised widgets in config — heading, text (lexical), image, buttons, icon list, columns, divider, spacer, gallery, carousel, video, hero, CTA, cards, accordion, and one that embeds a saved composition. Every one carries the same `style` group: padding, margin, background, text colour, radius, border, shadow, width, alignment, **per-breakpoint visibility**, anchor id, CSS class. **Wygląd → Komponenty** keeps the collection but changes meaning: it now holds *compositions* — "grid, photo left, heading + copy + button right", saved under a name and dropped into any page as one item. `pages.layout` is still an ordered list of sections, but a section now holds a tree of elements instead of pointing at a document. Write-up: `docs/page-builder.md`.
- **The nesting is fixed at one level** (`section → elements → columns → column → elements`). Payload blocks cannot reference themselves, and a bounded depth keeps the generated types and the Postgres tables finite. Compositions are **referenced, not copied**, with a depth guard, because nothing stops an editor putting a composition inside itself.
- **One set of renderers draws the canvas and the site** (`src/components/elements/`), which is what killed `admin/appearance/previews/` and the old `page-blocks/*`. Three constraints fell out of it, and they explain most of the odd-looking choices: (1) **no functions in the context** — the site renders these from a Server Component, so `ElementCtx` is `{ mode, labels, depth }` and media/compositions are resolved *into the data* first (Payload `depth` on the site, REST fetch in the panel); (2) **no Tailwind and no next-intl in the admin** — layout moved to `src/styles/elements.css`, imported by `globals.css` *and* `custom.css`, and a11y strings travel in `ctx.labels`; (3) **container queries, not media queries** — the canvas fakes a phone by shrinking, so a media query would keep answering for the desktop viewport. The lightbox is portalled to `document.body`, because `container-type` makes `.bw-el-root` a containing block for `position: fixed`.
- **The inspector is Payload's own `RenderFields`.** Given the selected block's client fields plus `parentPath` and `parentSchemaPath`, it renders lexical, upload pickers, relationship selectors, conditions and validation with nothing hand-written. Payload composes a block row's schema path as `${blocksFieldSchemaPath}.${blockSlug}`; `model.ts` derives both path spaces from the fixed nesting rather than walking the client schema.
- **`dbName` on a block must be a function.** A bare string **replaces the whole table name**, so `dbName: 'hero'` would collapse every hero block in the config into one table. It is a `({ tableName }) => …_b_hero` function everywhere, plus `dbName: 'components'` on the collection — together they keep the deepest identifier (`components_b_col_c_b_hero` + `_style_background_token`) under Postgres's 63-character cap, which the first build hit head-on. Group fields have no `dbName` at all, so the shortening has to happen at block/array level.
- **Nothing in an element is `required`.** An editor drops a gallery in and picks photographs afterwards; a required field would block saving the page in between.
- **`payload run` needs top-level `await`, not an async `main()`.** Wrapped in a function, the module finishes evaluating while the promise is still pending, Node finds no open handle, and the process exits with **code 0 having printed only the first line** — which reads exactly like a script that ran and did nothing. That is the real cause of "every `payload run` script stalls", noted on 2026-07-29 and blamed on the schema-push prompt; `src/seed/appearance-samples.ts` never had the problem because it was written at module scope. `scripts/smoke-page-builder.ts` is now too.
- **Unpublishing means `data: { _status: 'draft' }` *without* `draft: true`.** With the flag, Payload writes a new draft *version* and leaves the published row in the collection's own table, so the page stays live — the smoke test caught it.
- **Verified:** the dev database was dropped and rebuilt at the user's call (`docker compose down -v`), the new schema pushed clean, and `pnpm smoke:builder` is **11/11**: sections, elements in a section, a two-column row with nested elements in both columns, a saved composition resolved to its own content at `depth: 3`, a hidden section kept in the data, an unknown path and a draft both 404, and the path free after deletion. `pnpm seed:appearance` writes the three sample compositions. `pnpm build` green, `tsc` clean, `pnpm check:messages` clean (`Gallery` dropped from the client namespaces — the builder's gallery takes its labels as props now).
- **Watch out:** the wipe took **everything** with it — media, the 62 blog posts, users. The first visit to `/admin` will ask for a new user. **The builder UI is still not visually verified**: it typechecks, builds and is in the import map, and the data model is verified end to end, but nobody has clicked through the canvas. Upload population inside elements is the one assertion the smoke test skipped, because the fresh library has no files yet. `pnpm lint` is broken on `main` too (eslint-plugin-react 7.37 vs ESLint 10, fails while linting `eslint.config.mjs`).

## 2026-07-29: page builder, and the dev server has a blocked prompt nobody had noticed

- **Done:** a page builder in **Strony → Nowa strona**, built from the components in **Wygląd → Komponenty**. `pages.layout` is an ordered list of *placements*: a component plus this page's own width, vertical spacing, background, anchor and a hide switch. The builder replaces Payload's stock array UI with a library rail, a canvas that renders each section live, and an inspector. Full write-up in `docs/page-builder.md`.
- **The placement/component split is the design decision.** One "CTA: bezpłatna konsultacja" can sit on a dark full-bleed band on one page and in a narrow column on another, and editing its copy in the library updates both. Duplicating the component to change a background would have thrown that away.
- **Every mutation goes through the form's own row actions** (`addFieldRow`, `moveFieldRow`, `removeFieldRow`, `DUPLICATE_ROW`, `useField` per control), which is what Payload's own `ArrayField` does. No parallel store, so drafts, versions, validation and the unsaved-changes prompt keep working, and deleting the custom component leaves the data editable in the stock UI. **Selection is keyed by row id, never index**, or moving a section re-points the inspector at a different one.
- **Also built the public renderer, because a builder that publishes nothing is the "data only" state the docs already flagged.** `src/components/page-blocks/` renders all six types (two client components: gallery lightbox, embla carousel), served from the existing `[locale]/[...rest]` catch-all, which keeps its 404 job. Catch-alls have the lowest routing priority, so `/cennik` stays the coded page.
- **Verified on a production build, against a real page with all six types:** 5 of 6 sections rendered and the hidden one skipped; `max-width` caps 1440/1440/960/960 with the `full` section uncapped; spacing `none/lg/md` → `0/5rem/3rem`; background resolved to `var(--bw-surface-alt)`; anchor `id="korzysci"`; 21 images. `/` 200, `/en/<slug>` **404** (the `docs/i18n.md` fallback rule), unknown path 404, `/cennik` still 200, page present in the sitemap. A **draft** page 404s and a section whose component was deleted renders nothing while its siblings still render. Fixtures deleted afterwards: `pages` back to 0.
- **The thing that cost the most time, and it was not mine.** Every `payload run` script and every request that boots Payload stalls for minutes. Cause: Payload's dev schema push is sitting on a **`DATA LOSS WARNING … (y/N)` prompt** wanting to drop stale `sizes_thumb_*` and `sizes_large_*` columns from `media`, left over from an earlier `imageSizes` change. With no TTY it blocks, and every request queues behind it. I proved it was pre-existing by stripping the catch-all back to the committed `notFound()` original: **it hung identically**. **Do not answer `y`**, that is the data loss. `pnpm build` + `pnpm start` is the dependable route, because production disables the push. The drift wants a written migration, and it is not this task's to make.
- **`payload run` only rewrites aliased imports.** A script that reaches into `src/` with a relative `../src/…` path gets a file that cannot resolve `@payload-config`, and the process dies **with no output and exit code 0**, which reads exactly like a script that did nothing. Use `@/lib/…`. Cost an hour.
- **`embla-carousel` was never a direct dependency**, so `CarouselArrows`'s `import type { EmblaCarouselType } from "embla-carousel"` fails to resolve under pnpm 11's stricter hoisting: a pre-existing `tsc` error on `main`. Taken from `embla-carousel-react`'s own `UseEmblaCarouselType` instead, no dependency added.
- **The React Compiler caught the same rule twice more** (`set-state-in-effect`), making it seven times on this project. `useSiteComponents` derives `loading` from a request counter; `CarouselTrack` subscribes to embla's `select`/`reInit` rather than reading the snap synchronously.
- **Watch out:** the builder UI itself is **not visually verified**, for the reason recorded on 2026-07-28: there is still **no user account in this database**, so every admin route serves the login screen. It typechecks, lints, builds and is in the import map, and the data model behind it is verified end to end, but somebody has to log in and look at it. Also: `revalidate = 3600` on the catch-all means a page edited in the panel takes up to an hour to appear, same trade as the blog.

## 2026-07-28: the accordion's desktop pill was showing on phones

- **Done:** the "DOWIEDZ SIĘ WIĘCEJ" pill was rendering at every width, so on a phone it sat beside the mobile chevron and squeezed the row title to 145px, at which point long names wrapped and ran across the button. The show/hide moved to a wrapper span. Measured after: at 485px the title is 303px on one line, the pill is `display: none` and the chevron shows; at 1169px the pill shows and the chevron is `none`. - **The trap, remember this one:** `cn` in this project is a plain `join`, **not** `tailwind-merge`. ## 2026-07-27: image delivery, the `sizes` hint was the whole problem

- **Done:** `/blog`'s first screen went from **518KB to 208KB of image data (−59%)** at 2x. Three changes: honest `sizes` on the grid cards, AVIF enabled, and author portraits pointed at the 400px variant instead of the 768px one.
