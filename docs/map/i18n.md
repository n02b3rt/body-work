> Read when: adding a translated string, a bilingual page, or an English version of a post.

# i18n (PL/EN)

next-intl carries UI strings; Payload carries content. Default locale is `pl`, English lives behind
an `/en` prefix. Everything ships bilingual from the start, never "Polish for now".

## Configuration

`src/i18n/`

| File | Does |
|---|---|
| `routing.ts` | locales, default, prefix strategy |
| `request.ts` | per-request config, message loading |
| `navigation.ts` | locale-aware `Link`, `redirect`, `usePathname` |
| `client-namespaces.ts` | **the allowlist of namespaces shipped to the browser** |

Locale routing is composed with the dashboard-host gate in `src/proxy.ts`, which is Next.js 16's
renamed `middleware.ts`.

## Strings and formatting

- `messages/pl.json`, `messages/en.json`: add every key to both
- Dates and times: `src/lib/format-date.ts` (`formatDatePl`, `formatDateTimePl`), or next-intl
  `useFormatter().dateTime(value, 'dateTime')`. Never ad-hoc `toLocaleString` in UI; storage stays ISO/UTC
- Slugs: `src/lib/format-slug.ts`, Polish-aware transliteration in `src/lib/users/slugify-pl.ts`

## Content translation

Posts use the `PostTranslations` collection rather than `localized: true`, because that migration
hangs on an existing table. Helper: `src/lib/post-translation.ts`. Drafting help:
`src/components/admin/EnglishVersionPanel.tsx`.

## Gotchas

- **Only 11 of 46 namespaces reach the browser.** `getMessages()` is 188 KB; client components need
  7.1 KB. A `"use client"` component reading an unlisted namespace renders the **key path**. Add it
  to `client-namespaces.ts` and verify with `pnpm check:messages` (`scripts/check-client-messages.mjs`).
- **Prefer keeping a component on the server** and passing the string down as a prop, over adding a
  namespace to the client bundle.
- **No translation means the page or post 404s in EN.** No half-translated skeletons, by decision.
- **CMS builder pages are Polish-only.**
- **Legal documents and staff biographies stay Polish on purpose.** A mistranslated privacy policy is
  legal exposure, not a copy nit.
- **PL/EN key counts legitimately differ** (`Blog.categoryLocative.*` declines in Polish, not in
  English; `BlogTeasers` guards with `t.has()`). A mismatch is not automatically a bug.
